# MD-WBS-Tools 開発憲章（Development Charter）

## 1. プロジェクトの目的と背景

### 1.1. 目的

本プロジェクトの**究極的な目的**は、多くのビジネス現場で利用されている**Excel上のWBS（Work Breakdown Structure）情報を、Microsoft CopilotのようなAIアシスタントが正確に解釈・活用できる形式（`simple-md-wbs`）に変換する**ことである。

### 1.2. 背景

ExcelはWBS管理に広く使われているが、その多くは人間が視覚的に理解することを前提に作られている。とくに、サマリータスクが詳細タスクの下に配置される「ボトムアップ集計」形式や、日付・工数を算出する「数式」、タスクの親子関係を示す「グループ化（アウトライン）」は、AIがそのままの形で構造を理解する上での障壁となる。

この「**人間には分かりやすいが、AIには分かりにくいExcel WBS**」と、「**AIが理解しやすい構造化データ**」との間に存在するギャップを埋めることが、本プロジェクトが解決すべき核心的な課題である。

## 2. プロジェクトのスコープ

### 2.1. スコープ内（やること）

1. **Excelから`simple-md-wbs`への変換:**
    * **（フェーズ1）基本変換:** Excelの列情報（例: 大分類、中分類、タスク名）から、基本的な階層構造を持つ`simple-md-wbs`を生成する。
    * **（フェーズ3）高度な変換:** Excelの数式（の計算結果）やグループ化情報を解析し、日付、工数、より正確な階層を`simple-md-wbs`に反映させる。
2. **`simple-md-wbs`とCSVの相互変換:**
    * `simple-md-wbs`を中間形式として、他のツールと連携するためのCSV入出力機能を提供する。
3. **PowerShellスクリプトとしての提供:**
    * すべての変換機能は、PowerShellスクリプト（Cmdlet）として提供する。

### 2.2. スコープ外（やらないこと）

* **Excelファイルへのマクロ埋め込み:** SharePoint Online等の環境での利用を考慮し、ツールがExcelファイル自体を変更することはない。
* **リアルタイム同期:** Excelファイルへの変更をリアルタイムで監視・同期する機能は提供しない。変換は常にユーザーが手動でスクリプトを実行する形式とする。
* **GUIの提供:** 操作はすべてコマンドライン（CLI）で行う。
* **SharePoint Onlineとの直接連携:** ファイルのダウンロード/アップロードはユーザーが行うことを前提とし、ツールが直接クラウドストレージにアクセスすることはない。

## 3. 主要な成功基準

1. **Excelからの基本変換機能が実用的に動作すること（最重要）:**
    * 指定されたExcelテンプレートから、階層構造と基本的なタスク属性が`simple-md-wbs`形式で正しく出力される。
2. **生成された`simple-md-wbs`をCopilotが理解できること:**
    * 出力されたファイルをCopilotに読み込ませた際、プロジェクトのタスク構造や担当者、期日について正しく応答できる。
3. **ドキュメントが整備されていること:**
    * ユーザーがツールのセットアップと基本的な変換を、マニュアルにしたがって独力で実行できる。

## 4. 技術選定とアプローチ

* **中核技術:** **PowerShell + COM (Component Object Model)**
  * **理由:**
    * Windows環境に標準で搭載されており、追加のランタイムインストールが不要。
    * `COMインターフェース`を通じて、Excelアプリケーションを直接操作できるため、ファイル形式の複雑さを抽象化し、数式���グループ化といったリッチな情報を取得できる可能性がある。
    * マクロを埋め込む必要がなく、セキュリティポリシーが厳しい環境でも利用しやすい。
* **開発アプローチ:** **段階的開発**
  * 最初にもっとも価値の高いコア機能（Excelからの基本変換）を実装し、その有効性を確認した上で、段階的に機能を拡張していく。詳細は[プロジェクトロードマップ](./01_project_roadmap.md)に定める。
